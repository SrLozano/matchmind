# Polymarket Integration

This document records the current Polymarket decisions for Matchmind. It is intentionally practical: what we use, what we avoid, how data moves, and where the code lives.

## Product Role

Polymarket is the prediction-market layer for Matchmind. It should be described to users as crowd probability or market signal, not truth.

Best v1 use:

- World Cup winner markets
- Group winner markets
- Team advancement/progression markets
- Reach-stage markets
- Continent winner markets
- Top goalscorer markets
- Tournament-level market signals
- Chat context for long-term bets

Avoid in v1:

- Daily match winner predictions
- Totals, handicaps, cards, corners
- Anything requiring active fixture-level Polymarket coverage

The exploration found many active tournament markets, but no active/open World Cup 2026 match-level markets. That is why the implementation is deliberately narrow.

## Data Flow

Chat and UI reads do not call Polymarket directly.

```text
Polymarket Gamma/CLOB APIs or local discovery JSON
-> internal refresh/seed endpoint
-> Supabase tables
-> in-memory TTL cache
-> /chat and /polymarket/signals
```

This mirrors the API-Football cache design and keeps chat resilient when providers fail. In `/chat`, Polymarket context is best-effort: if the cache read or fallback discovery read fails, the route logs the issue, omits the market-signal block, and still asks the coach to answer from the remaining context.

## Endpoints

`GET /polymarket/signals`

Returns compact active World Cup 2026 signals from Supabase/memory. This is for UI surfaces such as Market Signals or future Pronósticos cards.

Query parameters:

- `limit`: 1-50, default `16`.
- `market_type`: optional filter. Must be one of the supported market types.

`POST /polymarket/seed-from-discovery`

Internal endpoint protected by `X-Internal-Token`. Reads `POLYMARKET_DISCOVERY_PATH`, normalizes the discovered markets, upserts `polymarket_markets`, and inserts snapshots. This is the bootstrap path for machines or networks where Polymarket is blocked.

`POST /polymarket/refresh`

Internal endpoint protected by `X-Internal-Token`. Fetches fresh data from Polymarket Gamma search and CLOB midpoint/spread/book endpoints, then writes the same Supabase tables. This is the intended scheduled refresh path during the tournament from an environment that can access Polymarket.

## Supabase Tables

`polymarket_markets`

Current/latest state for each market. Chat and `/polymarket/signals` read from this table.

Important fields:

- `polymarket_market_id`: unique market ID used for upserts.
- `condition_id`: CLOB condition ID when available.
- `market_type`: Matchmind-derived category such as `tournament_outright`, `group_winner`, or `advance_to_knockout`.
- `matched_team`, `matched_teams`, `matched_group`, `matched_player`: Matchmind mappings used to connect messy market text to product concepts.
- `yes_price`, `no_price`: extracted outcome prices. `yes_price` is treated as crowd implied probability.
- `liquidity`, `volume`, `best_bid`, `best_ask`, `midpoint`, `spread`: signal quality inputs.
- `match_confidence`: confidence that the market maps cleanly to a Matchmind concept.
- `signal_quality_score`: 0-100 derived score for liquidity, volume, spread, status, and matching confidence.
- `is_usable`: boolean shortcut for markets safe enough to show or inject into chat.
- `raw_payload`: full provider payload for debugging and parser improvements.

`polymarket_market_snapshots`

Historical observations for price movement. This will power rising signals and market momentum later.

Important fields:

- `polymarket_market_id`: links to `polymarket_markets`.
- `yes_price`, `no_price`, `liquidity`, `volume`, `best_bid`, `best_ask`, `midpoint`, `spread`: values at the snapshot time.
- `signal_quality_score`: quality at that moment.
- `fetched_at`: snapshot timestamp.

## Market Type Classification

`market_type` is not generated by an LLM. It is deterministic rule-based text classification.

The service combines Polymarket text fields:

```text
event_title
event_slug
market_question
market_slug
```

Then it normalizes the text and applies string/regex rules.

Current supported market types:

```text
tournament_outright
group_winner
advance_to_knockout
reach_stage
continent_winner
top_goalscorer
squad_inclusion
```

Current mapping:

```text
group + winner/win group/top group
-> group_winner

winner/champion/win the world cup/lift the world cup
-> tournament_outright

qualify/advance/progress/make the round/reach
-> advance_to_knockout

reach/make + final/semi-final/quarter-final
-> reach_stage

world cup + continent + win/winner
-> continent_winner

top goalscorer/golden boot/most goals
-> top_goalscorer

squad/roster/convocatoria/lista
-> squad_inclusion

vs/v/versus/draw
-> match winner, currently not user-facing for Polymarket

club world cup / women's world cup / cricket / rugby / etc.
-> unrelated/noise
```

Known caveat: `squad_inclusion` is supported by the parser but currently capped out of the default diversified signal feed, because these markets are less central to the v1 betting coach experience.

## Chat Behavior

Chat gets Polymarket context only when the user asks about a supported long-term market.

Examples that should use Polymarket:

- "Should I bet Spain to win the World Cup at 9.00?"
- "Is France good value to win its group?"
- "Will Mexico advance from the group?"
- "Can Brazil reach the semifinals?"
- "Is Mbappé top goalscorer worth it?"

Examples that should not use Polymarket yet:

- "Spain vs Germany over 2.5 goals"
- "Brazil to beat Japan today"
- "Argentina -0.5"

If a supported market type is detected but no usable market is found, the context explicitly says no useful Polymarket signal exists. The coach should treat that as absence of signal, not evidence for or against the bet.

## Operational Notes

Environment variables:

```text
POLYMARKET_DISCOVERY_PATH=tmp/polymarket_world_cup_discovery.json
POLYMARKET_GAMMA_BASE_URL=https://gamma-api.polymarket.com
POLYMARKET_CLOB_BASE_URL=https://clob.polymarket.com
POLYMARKET_CACHE_TTL_SECONDS=600
POLYMARKET_REFRESH_CLOB_TOKEN_LIMIT=40
POLYMARKET_MIN_MATCH_CONFIDENCE=0.7
POLYMARKET_MIN_SIGNAL_QUALITY=40
```

Bootstrap from local JSON:

```bash
curl -X POST http://localhost:8000/polymarket/seed-from-discovery \
  -H "X-Internal-Token: $INTERNAL_API_TOKEN"
```

Refresh from Polymarket APIs:

```bash
curl -X POST http://localhost:8000/polymarket/refresh \
  -H "X-Internal-Token: $INTERNAL_API_TOKEN"
```

The live refresh endpoint should be run from an environment that can access Polymarket. If a local/company network blocks Polymarket, use the seed endpoint for development. Runtime reads prefer Supabase, then fall back to the local discovery JSON if the table is empty or unavailable.
